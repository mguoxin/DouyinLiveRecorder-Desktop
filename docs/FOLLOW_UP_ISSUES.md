# DouyinLiveRecorder-Desktop 0.1.0 后续问题清单

- 建立日期：2026-11-18
- 对应发布版本：0.1.0（Git Tag `v0.1.0`）
- 用途：记录 0.1.0 发布时已知但未在本次发布中解决的问题，作为后续版本（0.1.x / 0.2.0）的正式输入。
- 说明：本清单中的问题**均不阻断 0.1.0 发布**，也不影响已发布 ZIP 的完整性；正式发布包与
  `v0.1.0` 标签保持不变。

## 状态与优先级

- 状态：`待决策`（需要产品/所有者决定）、`待执行`（方案明确，等待排期）、`待验证`（需特定环境）。
- 优先级：`P1` 影响数据安全或核心可用性；`P2` 影响体验或分发质量；`P3` 长期维护事项。

## 问题清单

### FU-001 低配机器（i3 / 4GB）真机验收

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1（发布时经所有者决定暂缓） |
| 状态 | 待验证（缺少目标机器） |
| 影响 | 低配环境下的内存、CPU、启动与长时间运行表现尚无真机结论 |
| 当前事实 | 已有 24 小时采样、开发机 20 房间基准与 2 核亲和性近似测试；均不能替代真机验收 |
| 建议动作 | 在真实 i3 / 4GB 机器执行 `tools\acceptance_low_spec.ps1 -Mode all`，回传 JSON 与日志 |
| 验收标准 | 20 房间全部 LIVE；峰值工作集 ≤ 300MB；关闭 ≤ 2s；GUI 采样 ≥ 2、增长 ≤ 30MB、CPU 平均 ≤ 25%；退出码 0 |
| 备注 | 通过前不得在任何材料中标记“低配验收通过” |

### FU-002 数据库损坏情况下的安全恢复限制

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 状态 | 待决策 |
| 影响 | 当前数据库已损坏且存在恢复请求时，恢复流程会先复制并校验当前库作为安全副本；校验失败即中止恢复，用户即使持有有效备份也无法通过界面完成恢复 |
| 当前行为 | 采用“失败保留现场、不替换数据库”的安全策略，属有意设计，但可能形成恢复死角 |
| 建议动作 | 由所有者决定是否改为“将损坏库重命名为 `app.db.corrupt-<时间戳>` 后继续恢复”，并保留原文件；需补充损坏库 + 有效备份的回归测试 |
| 验收标准 | 损坏库场景下可用有效备份恢复；原损坏文件仍保留可追溯；恢复正常路径与备份校验不受影响 |

### FU-003 自动录制开启时手动停止后会再次开始

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 状态 | 待决策 |
| 影响 | 直播中用户手动点击“停止录制”，下一个监控周期会按“直播中即录制”语义重新开始，容易被理解为停止无效 |
| 当前行为 | 已记录为 0.1.0 已知语义；界面未区分“自动停止”和“用户手动停止” |
| 建议动作 | 确定产品语义：A. 手动停止后暂停该房间自动录制，直到下播再开播或用户显式恢复；B. 保持现状但在界面明确提示 |
| 验收标准 | 选定方案后行为一致、可预测；补充自动录制与手动停止交互的回归测试；文档同步 |

### FU-004 Windows 代码签名

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 状态 | 待执行（需要代码签名证书） |
| 影响 | 未签名的 EXE 可能触发 SmartScreen“未知发布者”，影响首次运行信任与分发 |
| 建议动作 | 获取代码签名证书，对 `DouyinLiveRecorder.exe` 签名并加时间戳；在干净机器验证签名与 SmartScreen 表现 |
| 验收标准 | `Get-AuthenticodeSignature` 显示有效签名；干净环境首次运行无“未知发布者”阻断提示；签名不改变程序功能与数据目录行为 |

### FU-005 第三方依赖分发合规复核

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 状态 | 待执行（建议法务复核） |
| 影响 | 发布包内置 FFmpeg 9.0.2（GPL v3 构建）与 PySide6/Qt 6（LGPLv3）；大规模对外分发需确认许可义务 |
| 当前措施 | 包内附 `THIRD_PARTY_NOTICES.txt`、`licenses\FFmpeg-LICENSE.txt` 与 FFmpeg 构建说明；Qt 以动态链接方式分发 |
| 建议动作 | 由所有者/法务确认分发方式；必要时补充源码获取方式、书面要约与 LGPL 替换说明 |
| 验收标准 | 分发材料包含完整许可与来源说明；合规复核结论归档；后续升级依赖时重复复核 |

### FU-006 抖音页面结构变化带来的解析维护风险

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 状态 | 待持续跟踪 |
| 影响 | 生产解析器依赖公开直播页 React Flight 数据结构；页面改版可能导致状态无法识别，统一落入 `API_MALFORMED` |
| 当前行为 | 解析异常不会误开录制；无效房间不单独映射，统一按解析异常处理 |
| 建议动作 | 保留匿名会话验证工具 `tools\verify_real.py`；页面结构变化时更新解析与固定样本测试；考虑加入定期真实样本自检（需遵守匿名与授权边界） |
| 验收标准 | 页面改版后能快速定位并修复；固定样本回归通过；异常分类仍不会误判直播 |

未修改任何已发布源码、未移动或覆盖正式发布包、未改动 `v0.1.0` 标签。

后续启动 0.1.x / 0.2.0 开发时，建议先处理 FU-001、FU-002，再评估 FU-003 与 FU-004 的排期。
