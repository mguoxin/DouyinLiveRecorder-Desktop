## 2. 批次 F：FFmpeg 进程生命周期与异常恢复

### 2.1 实现要点

- 进程身份三元组：`(PID, 进程创建时间 FILETIME, 可执行文件路径)`，避免 PID 重用误杀。
- `KillOnCloseJob`（Windows Job Object，`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）：应用被强杀/崩溃时由内核关闭 Job，子进程随之终止。
- 登记表 `data/runtime/ffmpeg_processes.json`：原子写入；记录 recording_id、room_id、文件路径、启动时间。
- 启动清理 `cleanup_orphans()`：逐个核验创建时间、可执行文件名（`ffmpeg.exe`）、路径（登记时存在则必须一致）；任一不匹配即跳过并保留记录，不误杀其他软件的 FFmpeg。

## 3. 批次 G：清晰度与 Cookie 登录配置

### 3.1 实现要点

- 清晰度：`OD / UHD / HD / SD / LD` 映射到上游 `QUALITY_MAPPING`（0–4），默认 UHD；目标档位无可用流时按上游逻辑回退。
- 设置持久化到 `settings` 表（`recording.quality`），不改变 Schema。
- Cookie：Windows DPAPI（`CryptProtectData` + entropy + `UI_FORBIDDEN`）加密写入 `data/runtime/douyin_cookie.bin`（magic `DLR1`）；不写数据库、不回显、不进日志（仅记录长度）。
- 解析器每次解析按需读取 Cookie；读取失败按匿名访问降级；`RiskControlError` 时提示检查 Cookie 是否失效。

### 4.4 网络异常与恢复（真实链路故障注入）

方法：本地 CONNECT/absolute-form 代理（`%TEMP%\dlr-h\net\h_net.py`），FFmpeg 通过 `http_proxy` 走代理访问真实 CDN；「冻结」= 代理停止收发，模拟链路中断，不改 URL 签名、不伪造响应；解析接口直连（与生产一致）。

| 场景 | 步骤 | 实际结果 | 结论 |
| --- | --- | --- | --- |
| 网络短暂中断 | 录制稳定后冻结 8 秒（< `-rw_timeout 15s`） | 未断流：文件 1.0 → 8.5 MB，进程与记录保持 `recording` | 通过 |
| 网络长时间中断 | 冻结 90 秒，观察 FFmpeg 退出与续录 | 冻结 12 秒后 FFmpeg 以退出码 0 结束；重新解析确认直播中 → 自动续录（attempt 1/5），原分段标记失败并保留 8.97 MB；解冻后新分段增长至 2.12 MB，停止后 `completed` | 通过（修复后） |
| 修复前的行为 | 同上（旧逻辑） | 退出码 0 被当作直播结束，直接标记 `completed` 并停止录制（不再续录） | 已修复 |
| 流地址失效 / 连接失败 | resolver 始终返回不可达地址 | 有界重试：1 次初始 + 5 次续录，间隔 2/5/10/20/30 秒，共 105.3 秒；6 个分段全部 `failed`（0 字节），最终错误「自动续录失败（已尝试 5 次）」；登记表清空、无残留进程 | 通过 |
| 解析接口异常 | 单测覆盖传输错误 → `NETWORK_ERROR`；续录时解析失败按"无法确认状态"重试并受预算约束 | 自动化测试通过 | 通过（模拟） |
| 抖音风控 | 真实无效 Cookie | `RISK_CONTROL`，不崩溃、不误开录制；界面有提示 | 通过 |
| FFmpeg 超时 | `-rw_timeout 15s` 生效 | 长时间中断在 12 秒内触发退出并进入续录 | 通过 |
