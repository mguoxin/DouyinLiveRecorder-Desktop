## 3. P0-01 录制文件归档

### 3.1 设置项（`settings` 表，无 Schema 变更）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `archive.enabled` | `0` | 关闭时只记录 `archive_status='none'` |
| `archive.root_dir` | 空（= `<data>/archive`） | 归档根目录；允许与录制目录跨盘 |
| `archive.folder_template` | `{anchor}/{date}` | 支持 `{anchor}`/`{web_rid}`/`{date}`/`{session_id}` |
| `archive.name_template` | `{date}_{time}_{anchor}_{web_rid}` | 扩展名沿用源文件 |
| `archive.delete_source` | `0` | 校验通过后是否删除源文件（默认保留，安全优先） |

模板展开做白名单替换，未知占位符原样保留并记诊断；文件名清洗复用现有 `_safe_component` 规则。

### 3.2 数据库 Schema v3

`SCHEMA_VERSION = 3`。新增/变更：

```sql
ALTER TABLE recordings ADD COLUMN archive_status TEXT NOT NULL DEFAULT 'none';
ALTER TABLE recordings ADD COLUMN archive_path TEXT;
ALTER TABLE recordings ADD COLUMN archived_at TEXT;
ALTER TABLE recordings ADD COLUMN archive_error TEXT;
ALTER TABLE recordings ADD COLUMN archive_attempts INTEGER NOT NULL DEFAULT 0;

CREATE TABLE archive_jobs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    recording_id INTEGER NOT NULL REFERENCES recordings(id) ON DELETE CASCADE,
    source_path TEXT NOT NULL,
    target_path TEXT,
    status TEXT NOT NULL,              -- pending/copying/verifying/archived/failed/skipped
    attempts INTEGER NOT NULL DEFAULT 0,
    bytes_total INTEGER,
    sha256 TEXT,
    error TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
CREATE INDEX idx_archive_jobs_status ON archive_jobs(status);
CREATE INDEX idx_recordings_archive_status ON recordings(archive_status);
```

迁移 `V2→V3`：沿用现有 `_migrate` 模式，迁移前建立一致性备份，事务内 `ALTER TABLE` + 建表 + 回填 `archive_status='none'`，提交后执行完整性校验。失败回滚并保留备份。

### 3.3 归档状态机

```
none ──(录制完成/中断且有文件)──> pending
pending ──(worker 取任务)──> copying
copying ──(复制+SHA-256)──> verifying
verifying ──(目标存在且哈希/大小一致)──> archived（可选删除源）
verifying ──(不一致/IO 错误)──> failed（保留源，记录原因）
failed ──(手动/启动重试，次数<上限)──> pending
任意 ──(源文件不存在且目标已验证)──> archived
任意 ──(重复目标且哈希相同)──> skipped（去重，不覆盖）
```

不变式：

1. 正在写入的分段永不进入归档队列（仅在 `_close_segment` 之后入队）。
2. 目标文件先写 `.part`，校验通过后原子改名；同名且哈希不同则追加 `_1.._n`。
3. 只有目标文件通过存在性、大小与 SHA-256 校验后，才允许删除源文件。
4. 数据库状态不是唯一依据：启动恢复与重试均重新校验磁盘。
5. 每个任务有 `archive_jobs` 记录，状态、尝试次数、错误、哈希可追溯。

### 3.4 并发与故障恢复

- `ArchiveService` 单工作线程 + FIFO 队列 + 去重集合（按 `recording_id`），不新增每房间线程。
- 启动时：扫描 `archive_jobs` 中 `pending/copying/verifying` 与 `recordings.archive_status='pending'`，逐条校验磁盘后恢复；孤儿 `.part` 清理。
- 崩溃窗口：若 `.part` 已完整但未改名，重试时重新复制；若目标已存在且哈希匹配，直接归档。
- 跨盘：复制 + 校验 + 删除，禁止直接 `os.replace`。
- 磁盘不足：预检查目标卷剩余空间（`size * 1.05`），不足则 `failed` 并保留源。

## 4. P0-02 录制库与存储管理

### 4.1 查询模型

`domain/recording_query.py`：

```python
@dataclass(frozen=True)
class RecordingQuery:
    keyword: str = ""          # 主播/房间/文件名
    date_from: str = ""        # YYYY-MM-DD
    date_to: str = ""
    status: str = ""           # completed/failed/interrupted/recording
    archive_status: str = ""
    min_size: int = 0
    max_size: int = 0
    limit: int = 500
    offset: int = 0
```

`Database.search_recordings(query)` 使用参数化 SQL；关键字匹配 `display_name_snapshot`、`web_rid_snapshot`、`file_path`、`archive_path`。

### 4.2 一致性检查

`RecordingLibraryService.scan_consistency()`：

| 情况 | 标记 |
| --- | --- |
| 记录存在、文件存在、大小一致 | `ok` |
| 文件存在、大小不一致 | `size_mismatch`（不自动改库） |
| 记录存在、文件缺失（非 recording） | `missing` |
| 归档记录存在、归档文件缺失 | `archive_missing` |
| 磁盘存在、数据库无记录 | `orphan_file`（只提示，不自动删除） |

检查在后台线程执行，结果只读展示，不修改用户文件。

### 4.3 安全删除

- 仅对用户显式勾选的行启用；`recording` 状态禁用。
- 删除前二次确认（数量 + 总大小 + 不可恢复提示）。
- 文件移入 Windows 回收站（`SHFileOperation`），失败则拒绝并提示，不静默永久删除。
- 删除成功后更新记录为 `deleted`（新增状态值，仅用于展示），不物理删除数据库历史；归档副本存在时提示用户。

### 4.4 统计

- `storage_stats()`：按主播、日期、归档状态聚合 `COUNT/SUM(file_size)`。
- 磁盘：`shutil.disk_usage` 展示录制目录与归档目录所在卷的可用空间。
- 预警：低于设置阈值（复用磁盘阈值）时在页面顶部提示，不自动清理。

## 5. P0-03 解析适配层

### 5.1 分层

```
DouyinParser（既有接口，保持兼容）
  └─ DouyinParseAdapter
       ├─ contracts.py     RoomSnapshot 校验（字段、类型、范围）
       ├─ sources.py       ParseSource 协议 + FlightPageSource（唯一生产源）
       ├─ resilience.py    重试/退避/熔断（按源隔离）
       └─ errors.py        解析错误分类（复用 ParseResult）
```

### 5.2 契约校验

```python
@dataclass(frozen=True)
class RoomSnapshot:
    web_rid: str
    room_id: str
    status: int
    title: str
    stream_url: str | None
    raw_status: object
```

校验规则：

- `web_rid` 必须与请求一致；`status` 必须为 `int` 且在 `{2,4}`；`roomId` 必须为非空字符串或整数。
- 缺失/类型不符 → `API_MALFORMED`，不返回 `SUCCESS`。
- 未知响应体 → `API_MALFORMED`；风控特征 → `RISK_CONTROL`；空体 → `EMPTY_RESPONSE`；传输失败 → `NETWORK_ERROR`。

### 5.3 抗变更策略

- 源解析器与业务逻辑解耦：源只返回 `SourceResponse`，适配器负责标准化。
- 单源失败不抛出到监控循环；适配器返回分类结果并记录结构化日志（字段名、期望类型、实际类型，不含原始隐私数据）。
- 重试：同一轮内指数退避（0.5s/1s/2s，最多 3 次），仅对网络类错误；契约错误不重试，直接分类。
- 熔断：连续 N 次契约错误后进入冷却（60s），冷却期内快速返回 `API_MALFORMED`，避免拖慢监控循环；成功即恢复。
- 多房间并行：适配器无共享可变状态（熔断器按源 + web_rid 分桶），避免互相污染。

### 5.4 模拟接口变更测试

`tests/test_parser_contract.py` 使用真实页面结构的最小夹具：

- 正常响应；
- 缺 `status`、缺 `roomId`；
- `status` 变字符串、`roomId` 变对象；
- 嵌套结构变化（房间对象改名）；
- 风控页、空响应、HTTP 500、超时；
- 未知字段/未知结构不误判为成功；
- 连续失败触发熔断，恢复后正常；
- 多房间并行互不影响。
