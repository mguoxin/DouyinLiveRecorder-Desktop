## 2. v0.4.1 已实施内容（当前实际代码）

- P2-01：会话结束与分段结束事件已分离，`recording_finished` 载荷带 `scope=session|segment`，

  消费端 `main_window.py:_on_recording_finished`）。

  保留 40 行环形尾部（`ffmpeg.py:redact_stream_text`、`DEFAULT_STDERR_TAIL_LINES=40`），
  有界落盘 `data/logs/ffmpeg-stderr.log`（256 KiB 轮转，`_DiagnosticsLog`）；
  分段失败时把尾部写入日志（`recording_service.py:905-919`）。
- 退出流程改造：关闭确认、后台线程停止录制/监控、QueuedConnection 回到主线程、
  30 秒慢关闭提示（`main_window.py:closeEvent`、`_shutdown_worker`、`_on_shutdown_finished`）。
- 内置 FFmpeg 改为 LGPL 共享构建（BtbN `n9.0.2-61-gd59078794d`），补齐 19 份源码归档、
  70 个组件声明、94 份上游许可文本，新增 soxr 声明与许可原文。
- README 重写为 v0.4.1 下载入口；新增 GitHub Actions CI；LICENSE 与发布流程补齐。

### 3.1 已有诊断素材

- `app.log`：运行日志，含录制完成/失败、关闭耗时、续录尝试。
- `data/logs/ffmpeg-stderr.log`：已脱敏的 FFmpeg 输出（有界）。
- `Database.backup_to()`：一致性备份并做 `PRAGMA integrity_check`，可复用为“数据库完整性检查”。
- `recording.list_history()` / `db.list_recordings()`：可统计失败分段数量与时间。
- 缺失：一键汇总、路径脱敏、用户可控导出、体积裁剪、导出失败清理。

## 5. 已知限制（延续 v0.4.1 发布说明）

1. 未重新验证真实抖音直播录制链路。
2. “异常窗口空白”未复现、未消除。

## 6. 基线结论

- 项目处于**已公开发布的 v0.4.1 状态**，master、标签与 Release 同指 `7178d68`。
- 长期运行、断线续录、进程清理、备份恢复、凭据保护、stderr 诊断与关闭收尾均已有实现，
  v0.4.2 不应重复造轮子。
- 真正缺口集中在：**失败通知的用户可见性与事件阶段语义**、**用户主动诊断导出**、
  **窗口异常的现场复现能力**、**kill/低配/真实链路的专项实测**。
- 详细分类与实施计划见 `V0.4.2-ROADMAP.md`。
