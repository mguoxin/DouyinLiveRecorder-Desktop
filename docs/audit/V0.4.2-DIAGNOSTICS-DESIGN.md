# V0.4.2 一键诊断导出设计

- 目标：用户在遇到问题时，主动生成一份可自行检查、可手动提交给维护者的诊断包
- 硬性要求：隐私优先；只有用户明确操作才生成；绝不自动上传或联网发送
- 依据：现有 `app.log`、`ffmpeg-stderr.log`、`Database.backup_to()` 的完整性检查、
  `db.list_recordings()`、`settings_service` 配置读取能力

## 1. 可行性结论

**可行，且不需要改数据库 Schema。** 现有组件可直接复用：

| 素材 | 来源 | 处理方式 |
| --- | --- | --- |
| 运行日志 | `data/logs/app.log`（5 MB × 3） | 读取尾部，筛 WARNING/ERROR，脱敏后截断 |
| FFmpeg 诊断 | `data/logs/ffmpeg-stderr.log`（256 KiB） | 读取尾部，二次脱敏 |
| 数据库完整性 | `db.backup_to()` 内部 `PRAGMA integrity_check` | 只读连接执行 `PRAGMA quick_check`，不导出数据 |
| 录制异常 | `db.list_recordings()`、`sessions` | 仅统计失败/中断数量与时间范围 |
| 配置摘要 | `SettingsService.get_settings()` | 仅输出非敏感枚举/阈值 |
| 版本信息 | `dlrecorder.__version__`、`platform`、`PySide6.__version__` | 直接写入 |
| FFmpeg 版本 | 设置中的路径或内置 `tools/ffmpeg` / `_internal/ffmpeg` | `-version` 限时 3 秒，失败记录错误摘要 |

不新增依赖；不使用 psutil（内存信息可选，用 `ctypes` 的 `GlobalMemoryStatusEx`，失败则省略）。

## 2. 交互设计

入口：**设置页 →「导出诊断报告…」**（用户主动点击）。

流程：

1. 点击后先弹出说明：报告包含什么、不包含什么、仅保存在本机。
2. 后台线程生成（避免阻塞 GUI），显示可取消的进度对话框（复用现有进度组件风格）。
3. 成功后提示保存路径，并提供「打开所在文件夹」。
4. 失败时给出一条可读错误，删除临时文件，不留下半成品。
5. 不提供“上传”“发送”“反馈”按钮；不写任何网络代码路径。

默认文件名：`DLR-diagnostics-YYYYMMDD-HHMMSS.zip`，默认目录 `data/diagnostics/`（用户可改）。

## 3. 报告结构与内容

ZIP 内固定 4 个文件：

```
report.md                 人类可读摘要
report.json               同内容结构化（便于维护者脚本处理）
logs/app-errors.txt       最近的 WARNING/ERROR 行（脱敏、截断）
logs/ffmpeg-stderr.txt    FFmpeg 尾部（脱敏、截断）
```

### 3.2 report.md

固定小节：版本与环境、FFmpeg、配置摘要、数据库完整性、最近错误（最多 20 条）、
录制异常统计、隐私声明（已脱敏项与未包含项）、生成时间。不得包含完整数据库行。

## 4. 隐私与脱敏（硬性）

### 4.1 绝不包含

- Cookie、Token、密码、Authorization、DPAPI 凭据文件（**不读取** `douyin_cookie.bin`）。
- 完整带签名的直播流 URL 或任何 `http(s)` 链接。
- 数据库原始内容（不复制 `.db`，不导出 SQL 行）。
- Windows 用户名、主机名、用户目录绝对路径、桌面路径。
- 房间 ID 原值（默认掩码，见 4.2）。
- 剪贴板、浏览器数据、其他进程信息。

### 4.2 脱敏规则（按顺序执行，全部幂等）

1. **URL**：`https?://\S+` → `<url>`（同时消除签名参数与域名）。
2. **凭据字段**：`(?i)(a_bogus|msToken|sessionid|sessionid_ss|ttwid|signature|token|cookie|authorization|password)\s*[=:]\s*[^\s&"']+`
   → `\1=<redacted>`。
3. **路径**：先替换用户目录（`%USERPROFILE%` 实际值）为 `%USERPROFILE%`，
   再把数据目录替换为 `<data>`，其余 `[A-Za-z]:\\[^\s"']+` → `<path>`。
4. **身份**：`USERNAME`、`COMPUTERNAME`、`socket.gethostname()` → `<user>` / `<host>`；
   邮箱 `[\w.+-]+@[\w-]+\.[\w.]+` → `<email>`。
5. **IP**：IPv4/IPv6 字面量 → `<ip>`。
6. **房间号**：10 位以上数字串保留首 2 末 2，中间替换为 `*`（如 `95*******22`）。
7. **控制字符/超长行**：单行截断 2000 字符，去除 ANSI 转义。
8. 最后执行一次断言扫描：若仍匹配 Cookie/URL/用户路径模式，则丢弃该行并计数
   （`redaction_dropped_lines` 写入 report.json）。

### 4.3 二次校验

生成 ZIP 前，对全部文本再次运行 4.2 的检测正则；命中即视为构建失败（不生成包），
错误写入日志但不包含原文。测试中固定用含敏感样板的日志验证“零泄漏”。

## 5. 体积与裁剪

| 项 | 上限 |
| --- | --- |
| `app-errors.txt` | 256 KiB（从尾部向前，按行裁剪） |
| `ffmpeg-stderr.txt` | 128 KiB（尾部 200 行） |
| `report.json` / `report.md` | 各 64 KiB |
| 整个 ZIP | ≤ 1 MiB（压缩后）；超限先裁日志，再裁错误条数 |

裁剪按“从旧到新丢弃”，保留最近事件；在报告中记录 `truncated=true` 与被丢弃行数。

## 6. 失败清理与原子性

- 在 `data/diagnostics/.building-<uuid>/` 下构建，完成后 `zipfile` 写入同目录临时文件，
  `os.replace()` 原子移动到最终路径。
- `finally` 中递归删除 `.building-<uuid>`；任何异常都不得留下部分 ZIP。
- 目标文件已存在时自动追加 `-2`，不覆盖用户文件。
- 取消（用户关闭进度框）时设置取消标志，构建线程在下一个检查点退出并清理。

## 7. 安全边界

- 无 socket、无 requests、无 httpx 调用；诊断模块不导入网络栈。
- 不读取凭据文件；不查询 `settings` 中的 Cookie 字段。
- 数据库使用只读连接（`file:<path>?mode=ro`）执行 `PRAGMA quick_check`；
  若被写锁占用，记录 `busy` 并继续导出，不阻塞录制。
- 导出不修改数据库、配置或录制文件。

## 8. 测试计划（新增 `tests/test_diagnostics.py`）

1. 敏感样板：日志含 `https://pull-xxx.live...?sign=...&a_bogus=...`、
   `Cookie: sessionid=abc`、`C:\Users\alice\Desktop\...`、`alice@example.com`、
   `192.168.1.10`、房间号 `95694179922` → 导出后逐项断言不存在；房间号已掩码。
2. ZIP 内只有 4 个预期条目；无 `*.db`；二进制中不含 `SQLite format 3`。
3. 体积：构造 2 MB 错误日志 → 输出 ≤1 MiB 且 `truncated=true`。
4. 裁剪：仅保留最近错误，顺序正确。
5. 失败清理：注入压缩写入异常 → 目标目录无残留 ZIP、无 `.building-*`。
6. 只读性：导出前后数据库文件哈希不变、录制文件未被访问。
7. 网络隔离：以打桩的 `socket.socket` 断言导出期间未创建套接字。
8. 数据库忙碌：持有写事务时导出仍成功，`quick_check="busy"`。
9. 取消：构建中取消 → 无输出文件、无临时目录。

## 9. 修改文件、风险与回滚

| 文件 | 改动 |
| --- | --- |
| `infrastructure/diagnostics.py` | 新增：采集、脱敏、构建 ZIP（约 250–300 行） |
| `presentation/pages.py` | 设置页新增按钮与保存对话框 |
| `presentation/widgets.py` | 复用进度提示；新增隐私说明文本（不新建窗口框架） |
| `tests/test_diagnostics.py` | 新增 |

风险：

- D1 脱敏遗漏导致隐私泄漏 → 二次断言 + 失败即拒绝生成；测试覆盖已知模式。
- D2 读取大日志造成卡顿 → 只读尾部固定字节，后台线程。
- D3 数据库只读连接被锁 → 降级 `busy`，不阻塞。
- D4 用户误以为会自动上传 → 界面明确“仅保存在本机”，无网络按钮。

回滚：删除入口按钮并停止构建即可；不涉及 Schema、配置格式与发布资产。

## 10. 验收标准

- 仅用户点击后生成；默认不产生任何诊断文件。
- 敏感样板零泄漏；ZIP ≤1 MiB；失败无残留；导出期间录制与监控不受影响。
- report.md 能被非开发用户读懂，report.json 字段稳定（`schema=1`）。
- 全部新增测试通过，现有 284 项无回归。
