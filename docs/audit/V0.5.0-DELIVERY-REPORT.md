## 3. 数据库变更与迁移

- `SCHEMA_VERSION = 3`。
- `recordings` 新增：`archive_status`（NOT NULL DEFAULT 'none'，CHECK 七态）、`archive_path`、`archived_at`、`archive_error`、`archive_attempts`。
- 新表 `archive_jobs`（recording_id FK ON DELETE CASCADE、status CHECK、attempts、bytes_total、sha256、error、created_at、updated_at）。
- 索引：`idx_recordings_archive_status`、`idx_archive_jobs_status`、`idx_archive_jobs_recording`。
- 迁移：`V1→V2→V3` 链式；每一步写锁 + `BEGIN IMMEDIATE` + Online Backup 一致性备份 + 提交后校验；失败回滚；提交结果不确定时关闭连接并拒绝继续。
- 回滚：使用 `migration_backups/*.db` 恢复；`archive.enabled=0` 时行为与 v0.4.2 一致。

## 9. 已知问题与剩余风险

1. **真实抖音直播链路未验证**（BLOCKED）：无用户授权的在播测试直播间；仅离线夹具与匿名静态页历史结果。
2. **24 小时长稳未执行**（NOT TESTED）：仅 6 分钟多房间 soak。
3. **跨物理磁盘未实测**（NOT TESTED）：单卷环境；实现为复制+校验+删除，不依赖跨卷原子移动。
4. **归档时间模板使用开始时间（UTC）**：文件名中的日期/时间来自 `started_at` UTC；界面/文件名可能与本地时间相差时区。
5. **归档任务不自动清理**：每次重试新增 `archive_jobs` 行，长期运行会累积，需后续版本提供保留策略。
6. **一致性孤文件扫描**：仅识别常见媒体后缀，最多报告 500 个孤文件；不自动删除。
7. **录制库检索同步执行**：1 万条约 2 ms；10 万条以上未验证。
8. **界面人工验收有限**：录制库与指标面板以自动化/冒烟为主，未做多分辨率视觉走查。
9. **归档默认关闭**：升级后用户需在设置中显式开启；关闭时行为与 v0.4.2 一致。
