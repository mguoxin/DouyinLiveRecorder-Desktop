## 1. 已批准范围

### 1.1 一期范围（本次批准规划）

| 能力 | 口径 |
| --- | --- |
| 当前文件大小 | 当前分段输出文件字节数 |
| 分段录制时长 | 当前分段墙钟时长（单调时钟） |
| 本场录制时长 | 各分段录制时长之和，不含重连等待 |
| 估算写入速度 | 5 秒滑动窗口的 `Δsize/Δt`，界面标注"写入速度（估算）" |
| 数据停滞时间 | 距最近一次文件增长的秒数 |
| 健康状态 | 良好 / 恢复中 / 降速 / 停滞 / 重连中 / 失败 / 未录制 |
| 120 秒趋势图 | 1 秒一点的写入速度折线，环形缓冲 120 点 |
| 房间底部详情面板 | 仅显示当前选中房间；无选中时隐藏；可手动收起 |

### 1.2 明确不做

- 网络下载速度（不实施、不验证）。
- 媒体码率、FFmpeg 速度比（二期候选，未批准修改命令）。
- 新线程、新第三方依赖、新数据库字段、新 FFmpeg 参数、新用户配置项。
- 房间列表新增列（保持 7 列）。
- 状态栏总写入速度（本次决策未包含）。
- 指标持久化到数据库或诊断包。

### 1.3 硬约束

1. Schema v2 与 `recordings` 表结构不变。
2. 录制状态机、错误事件、通知去重、重连退避、120 秒停滞重启逻辑不变。
3. 健康状态是纯展示派生值；"停滞"不等于"录制失败"。
4. 采样沿用录制管理线程的 1 秒轮询；禁止新增线程。
5. 所有阈值使用模块常量；一期不提供用户配置。
6. 保持现有深浅主题令牌与组件风格。

## 3. 设计要点（实施契约）

### 3.1 指标模块接口

`recording_metrics.py` 只做计算，不访问文件、不访问 Qt：

```
SegmentMetrics
  update(now: float, size: int) -> None
  reset_segment(now: float, completed_size: int) -> None
  freeze() -> None
  snapshot(now: float) -> MetricsSnapshot   # frozen dataclass / 普通 dict 拷贝
```

固定常量（一期）：

| 常量 | 初值 | 说明 |
| --- | --- | --- |
| `SPEED_WINDOW_S` | 5.0 | 展示速度平滑窗口 |
| `TREND_POINTS` | 120 | 趋势图点数 |
| `STALL_WARN_S` | 30.0 | 停滞降级阈值 |
| `RECOVER_GRACE_S` | 10.0 | 恢复宽限期 |
| `DEGRADE_WINDOW_S` | 30.0 | 降速观察窗口 |
| `DEGRADE_BASELINE_S` | 60.0 | 降速基准窗口 |
| `DEGRADE_RATIO` | 0.4 | 降速比例阈值 |

> 初值只是校准起点。测试阶段须用合成增长曲线与本地 FFmpeg 短录制校准，并在验收报告记录误报率；校准后可调整常量，但不得引入用户配置。

### 3.2 快照结构

`metrics_snapshot(room_id)` 返回 `dict | None`（房间不在录制中返回 `None`）：

```
{
  "room_id": int,
  "state": "recording" | "reconnecting",
  "segment_seconds": float,
  "session_seconds": float,
  "current_bytes": int,
  "session_bytes": int,
  "write_bps": float,
  "stall_seconds": float,
  "health": "good" | "recovering" | "degraded" | "stalled" | "reconnecting",
  "trend": tuple[float, ...]   # 最多 120 个点
}
```

线程安全：模块内部锁；GUI 只拿拷贝，不持有内部对象。禁止在快照中返回可变引用。

### 3.3 服务接线

| 时点 | 动作 |
| --- | --- |
| `_handle_start` 成功 | 创建 `SegmentMetrics`，记录 `segment_started_at` |
| `_poll_active` 每 tick | `metrics.update(now, size)`；保留现有 `last_size/last_growth_at` 逻辑 |
| `_start_segment`（续录） | `metrics.reset_segment(now, completed_size)`；本场累计保留 |
| `_begin_reconnect` / 等待重连 | `metrics.freeze()`；状态由 `process is None` 推导 |
| `_close_segment` / `_finalize` | 冻结并保留最终快照直到房间行变为 idle |
| `_drop_active` | 移除指标对象，不留定时器或引用 |

现有 `recording_started / recording_finished / recording_error / recording_reconnecting / recording_recovered` 载荷保持不变。

### 3.4 UI 交互

- `MetricsPanel` 位于表格卡片下方，不新增表格列。
- 无选中房间：`hide()`，布局不保留空白。
- 首次选中：默认展开；手动收起后同一次运行内切换房间保持收起；清空选中后重置为默认展开。
- 选中未录制房间：面板可见，显示"该直播间当前未录制"。
- 重连中：写入显示 `—`，显示"第 x/y 次自动续录"。
- 停滞：红色状态点 + "已 N 秒无数据"；房间列仍显示"录制中"。
- 趋势图：自绘 `QPainter` 折线，120 点，使用 `tokens.accent`；无动画。
- 刷新：1 秒定时器，仅面板可见时运行；最小化、托盘隐藏、切换到其他页面时停止；仅更新选中房间。

## 6. 性能验收方案（决策 10）

### 6.1 目标机 50 房间

```
.venv\Scripts\python.exe acceptance\bench_metrics_50_rooms.py --rooms 50 --ticks 300
```

- 使用临时文件模拟增长，不改录制服务状态机；测量 `_poll_active` 增量耗时。
- 输出：mean、p50、p95、max、每房间内存。
- 通过：mean < 10 ms，p95 < 20 ms，max 不出现 > 100 ms 的离群值。

### 6.2 低配设备

- 同一脚本 + 实际 GUI 运行 30 分钟（10–50 房间）。
- 记录：CPU 增量、RSS 增量、界面交互是否卡顿、是否有定时器泄漏。
- 通过：CPU 增量 < 1%，RSS 增量 < 20 MB，界面操作无阻塞。

### 6.3 记录要求

设备型号、CPU、内存、磁盘类型（SSD/HDD/网络盘）、Windows 版本、杀毒软件、测试起止时间。**禁止用估算或纯 Mock 结果替代。**

## 8. 回滚方案

### 8.1 分级回滚

| 级别 | 触发条件 | 动作 | 影响 |
| --- | --- | --- | --- |
| R1 功能级 | 只影响指标显示 | `git revert C4`（必要时连 C3） | 录制不受影响，无需迁移数据 |
| R2 模块级 | 指标模块异常或性能不达标 | `git revert C2 C1` | 服务恢复原状；无库变更 |
| R3 紧急关闭 | 现场发现 UI 卡顿/异常 | 单提交将内部常量 `METRICS_ENABLED` 置 `False`（代码常量，非用户配置），停用采样与定时器 | 不删除代码，便于定位；录制继续 |
| R4 版本级 | 候选包不达标 | 放弃 v0.5.0 候选包，继续使用 v0.4.2 | v0.4.1 标签与 v0.4.2 候选不变 |

### 8.2 数据与构建安全

- 无数据库迁移，回滚不涉及数据恢复。
- 指标不写文件、不进诊断包、不上传。
- v0.4.1 标签、v0.4.2 候选包与 SHA-256 保持不变。
- 回滚后须重跑全量测试与一次录制冒烟，并在回滚记录中写明版本、提交与原因。
