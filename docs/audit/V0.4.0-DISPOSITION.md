# v0.4.0 历史版本许可处置方案

日期：2026-11-22
状态：方案已准备，**尚未对远端执行任何变更**
适用范围：GitHub Release `v0.4.0` 的二进制附件

## 1. 处置结论

v0.4.0 原始附件内置 gyan.dev 9.0.2 essentials **GPLv3 静态构建**的 FFmpeg
（`--enable-gpl --enable-version3`，静态 x264/x265/xvid）。经复核，gyan 未公开该构建的
第三方组件清单、构建脚本与工具链信息，**GPLv3 要求的完整对应源码无法验证齐全**。
因此该二进制不满足当前合规验收要求，处置如下：

1. **停止公开分发**该二进制附件（推荐“转为草稿”，可逆；备选“删除附件”，需先备份）；
2. **保留**原始 ZIP 的本地备份、SHA-256、`v0.4.0` 标签、Git 历史与发布记录；
3. 不覆盖原 ZIP、不修改其哈希、不改标签、不重写历史；
4. 补充包仅作为审计材料，**不得称为完整对应源码**；
5. 待取得完整材料或以合规构建替代后，再决定恢复分发或另发新版本。

## 3. 推荐操作（非破坏、可逆）

**首选：将 Release 转为草稿（draft）**

- 效果：Release 页面与附件对未登录/普通访问者不可见，停止公开下载；标签与仓库源码保持不变。
- 恢复：取消草稿即可恢复，附件不变、哈希不变。
- 入口：GitHub Release 页面 → Edit release → 勾选 “Save as draft” → Update release；
  或 API：`PATCH /repos/mguoxin/DouyinLiveRecorder-Desktop/releases/453783874`，
  body `{"draft": true}`。

**备选：仅删除二进制附件**

- 仅当确实需要彻底移除下载入口时使用；删除前必须完成本地备份与哈希核对。
- 恢复：重新上传同一文件，校验 SHA-256 一致；附件 ID 会变化，下载 URL 名称不变。
- 注意：若保留 `SHA256SUMS.txt`，其内容仍引用被删 ZIP，应在说明中标注。

**禁止**：覆盖同名附件、修改标签指向、删除仓库源码、强制推送、静默操作。
