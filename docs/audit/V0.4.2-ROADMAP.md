## 2. 工作项明细

### W-01 录制错误事件阶段化与通知中心

- 目标：准确区分“可自动恢复的重连”和“最终失败”；同房间同类错误 60 秒去重；
  多房间异常合并；恢复后提示一次；托盘不可用有降级；不影响录制。
- 修改文件：
  - `src/dlrecorder/application/recording_service.py`（`recording_error` 载荷 dict、
    `category/retryable/phase`、新增 `recording_recovered`）
  - `src/dlrecorder/presentation/notification_center.py`（新增）
  - `src/dlrecorder/presentation/tray.py`（severity 参数）
  - `src/dlrecorder/presentation/main_window.py`（接线、状态栏职责收敛）
  - `tests/test_recording_service.py`（5 处错误断言）、`tests/test_notification_center.py`（新增）
- 风险：
  - 信号载荷变更影响测试与消费端（中）；一次性更新，CI 必须全绿。
  - GUI 高频事件（低）；通知中心只做内存操作，合并窗口。
  - 文案误导（中）；禁止把重连写成失败，文案表见设计文档。
- 测试场景：单房间一次断网→恢复；连续 6 次失败；5 房间同时失败；托盘不可用；
  通知中心内部异常注入；关闭过程中收到通知。
- 验收标准：设计文档 §8 全部通过；现有 284 项无回归；无模态框；录制文件与历史不受影响。
- 回滚：停止连接通知中心，恢复原状态栏逻辑；不改数据库，可单提交回退。

### W-02 房间行“重连中/失败”状态

- 目标：续录等待期不显示“录制中”；失败后保留可见徽标直到用户处理或重新录制。
- 修改文件：`presentation/widgets.py`（`RoomListWidget` 状态渲染）、
  `presentation/main_window.py`（事件映射）、`tests/test_app.py`（扩展）。
- 风险：列渲染分支增多（低）；不新增列、不改布局骨架。
- 测试场景：reconnecting(2/5) → 行文本含“重连中 2/5”；recovered → 恢复“录制中”；
  session failed → 红色“录制失败”；删除房间后状态清理。
- 验收标准：三种状态在 offscreen 集成测试中可见且可回退；主题切换后颜色正确。
- 回滚：恢复原布尔录制态渲染。

### W-03 一键诊断导出

- 目标：用户主动生成脱敏诊断 ZIP，不联网、不自动生成、不包含敏感数据。
- 修改文件：`infrastructure/diagnostics.py`（新增）、`presentation/pages.py`（设置页入口）、
  `presentation/widgets.py`（进度/说明）、`tests/test_diagnostics.py`（新增）。
- 风险：脱敏遗漏（高影响，低概率）→ 二次断言扫描，命中即拒绝生成；
  大日志读取卡顿（低）→ 只读尾部字节 + 后台线程；
  数据库锁（低）→ 只读连接 + `busy` 降级。
- 测试场景：见设计文档 §8（敏感样板、体积、裁剪、失败清理、只读性、网络隔离、取消）。
- 验收标准：敏感样板零泄漏；ZIP ≤1 MiB；失败无残留；导出期间录制不受影响。
- 回滚：移除入口按钮与模块；无 Schema/配置变更。

### W-04 关闭期覆盖式进度

- 目标：关闭收尾时内容仍可见，用覆盖层显示“正在停止录制（第 n 个房间）”，
  避免整窗禁用的灰色空内容被误判为空白/卡死。
- 修改文件：`presentation/main_window.py`（`closeEvent` / `_on_shutdown_finished`）、
  `presentation/widgets.py`（轻量遮罩控件，复用主题色）；`tests/test_app.py`（扩展）。
- 风险：遮罩层事件穿透/残留（低）；必须在 `_on_shutdown_finished` 与取消路径统一移除。
- 测试场景：无录制关闭；有录制关闭；慢关闭注入（2 秒/10 秒）；关闭取消；
  收尾失败（`shutdown_ok=False`）仍正确解除遮罩。
- 验收标准：关闭期间内容区保持可见且可读；取消后遮罩消失；现有测试通过。
- 回滚：恢复 `central.setEnabled(False)` 的原实现。

### W-05 窗口异常现场记录

- 目标：为“窗口空白”提供可诊断证据，不改变正常行为。
- 修改文件：`presentation/main_window.py`（仅在 `DLR_WINDOW_TRACE=1` 时记录
  `visibility/geometry/windowState/isActiveWindow/screen/DPI` 于关键点：
  hide/show/restore/close/theme apply）；`infrastructure/diagnostics.py`（纳入最近 50 条快照）。
- 风险：埋点开销（极低，默认关闭）；日志噪声（仅在环境变量开启时）。
- 测试场景：开启变量后触发 10 次隐藏/恢复/主题切换，断言快照条数与字段；
  offscreen 环境下 DPI/屏幕字段降级不崩溃。
- 验收标准：默认无新增日志；开启后诊断包包含快照；无行为变化。
- 回滚：移除埋点或保持变量默认关闭。

### W-06 窗口空白根因复现

- 目标：在可控环境复现空白，至少覆盖：多显示器、125%/150% DPI、RDP 断开重连、
  低配机器、关闭收尾期间恢复窗口。
- 方法：`DLR_WINDOW_TRACE=1` + 手工/脚本化序列（最小化→托盘→恢复→切主题→关闭取消），
  每场景记录次数、截图、日志与 DPI/拓扑；异常窗口截图保存于用户本地，不自动上传。
- 修改文件：无（仅测试脚本，放 `tools/` 或本地临时目录，按需新增 `tools/window_probe.py`）。
- 风险：无法复现（高）；结论只能写“未复现 + 覆盖范围 + 剩余风险”。
- 验收标准：每个场景有明确次数记录；若复现，提交根因证据与最小修复方案再另行批准。
- 回滚：不涉及生产代码。

### W-07 FFmpeg kill 回退验证

- 目标：确认 `q → terminate → kill` 第三段可达且正确（`ffmpeg.py:462-484`）。
- 方法：
  - 单元层：注入伪造进程对象，`terminate()` 抛异常或进程仍存活 → 断言 `kill()` 被调用，
    且 `ProcessLookupError`/权限错误被吞掉并记录。
  - 集成层：用不响应 stdin 的本地子进程模拟 `ffmpeg`，验证超时后走 terminate/kill。
- 修改文件：`tests/test_ffmpeg.py`（新增用例）；生产代码仅在发现缺陷时修改。
- 风险：Windows `TerminateProcess` 立即生效，真实 kill 分支天然难触发（中）；
  以注入证明调用路径，不虚构真机数据。
- 验收标准：两条单元用例稳定通过；关闭耗时不超过 `stop_grace + shutdown_timeout`。
- 回滚：仅测试改动。

### W-08 低配真机与长时运行

- 目标：补齐 v0.4.1 未完成的低配验收与 24h 资源曲线，并测句柄/线程趋势。
- 方法：复用 `tools/benchmark.py --soak-hours 24 --rooms 20 --interval 1`、
  `tools/acceptance_low_spec.ps1 -Mode all`；新增句柄采样（`GetProcessHandleCount`）
  与线程数采样写入 JSONL；在 i3/4GB 真机执行。
- 修改文件：`tools/benchmark.py`（新增句柄采样，可选）、`tools/acceptance_low_spec.ps1`
  （汇总字段）；不修改应用运行逻辑。
- 风险：无目标设备（高）→ 若无法执行，保留“未验收”结论，不以模拟结果替代。
- 验收标准：24h 20 房间无中断；内存无单调增长；线程/句柄稳定；报告含机器信息与原始 JSONL。
- 回滚：仅工具改动。

### W-09 真实抖音链路复验

- 前置：用户明确授权、指定可录制的房间与时长、遵守平台条款。
- 内容：解析→LIVE→录制→停止→历史→续录（弱网模拟）→退出清理。
- 风险：账号/网络/平台风控；不得在未授权时执行。
- 验收标准：按用户授权范围记录成功/失败次数，不写入公开 Release 作为普适结论。
- 回滚：不使用生产数据目录，全部隔离。

## 3. v0.4.2 稳定性测试矩阵（专项 D）

| 场景 | 方法/夹具 | 观测指标 | 判定 |
| --- | --- | --- | --- |
| 连续运行 | `benchmark.py --soak-hours 24 --rooms 20` | 内存、线程、句柄、LIVE 率 | 内存无单调增长；20/20 稳定 |
| 多房间并发 | 20–50 Mock 房间，1–5 秒间隔 | 启动耗时、CPU、DB 写入 | 启动完成且无任务丢失 |
| FFmpeg 异常退出 | 注入伪进程提前退出/退出码 0 | 续录次数、分段文件、历史状态 | 按预算续录；最终状态准确 |
| 网络断开/恢复 | 本地 HTTP 流，限速/断流/恢复 | 停滞检测、重连时延、文件连续性 | 恢复后新分段可播放 |
| 自动续录 | 连续断流 6 次 | 退避序列 2/5/10/20/30、上限 5 | 不超过预算，不无限重连 |
| 磁盘不足 | 注入 `free_space_provider` 阈值 | 阻止开始/停止录制、文件保留 | 不自动删除；状态为失败 |
| 异常关闭清理 | 强杀进程后重启 | 遗留 FFmpeg、`interrupted` 回填 | 身份匹配才终止；大小回填准确 |
| DB/文件一致性 | 崩溃点注入：启动前/录制中/收尾中 | `recordings` 状态与磁盘大小 | 无“完成”但文件缺失；无悬挂 recording |
| 资源曲线 | 24h 采样 + 句柄/线程 | WorkingSet、HandleCount、ThreadCount | 无持续上升；无句柄泄漏 |
| 关闭路径 | 关闭取消/隐藏关闭/慢关闭/kill 回退 | 关闭耗时、窗口可见、退出码 | ≤ 关闭超时；无残留进程 |
| 通知风暴 | 10 房间同时断流 | 气泡数量、GUI 响应 | 合并为 1 条；录制不受影响 |

原则：

- 性能结论只引用实际测量（含机器信息、采样文件路径）；无数据不写数字。
- 优先使用本地生成媒体与本地限速 HTTP 流；真实抖音测试冻结（W-09 需授权）。

## 4. 实施顺序与门禁

1. **M1 语义与通知**：W-01 + W-02。先改事件载荷与测试，再接通知中心，
   最后做房间行状态。门禁：284 + 新增测试全绿，手工断网/多房间场景通过。
2. **M2 诊断能力**：W-03 + W-05。门禁：隐私样板零泄漏、体积与清理测试通过。
3. **M3 关闭体验与专项验证**：W-04 + W-07（+ W-06 尝试复现）。门禁：关闭路径注入通过，
   kill 回退单测通过。
4. **M4 发布前实测**：W-08（+ W-09 若获授权）。门禁：24h soak 与低配验收有报告；
   无回归；CI 绿；更新 `docs/RELEASE_0.4.2.md` 与 README；沿用 v0.4.1 发布/校验流程。

每个工作项独立提交、可单独回退；不得在同一提交混合重构与功能。

## 5. v0.4.2 验收标准（整体）

- 功能：断网时只出现“重连中”，恢复后一次“已恢复”，最终失败才提示“录制已停止”；
  诊断包可一键生成且零敏感泄漏。
- 质量：现有 284 项 + 新增测试全绿；CI 通过；无新增第三方依赖。
- 稳定：关闭无残留进程；24h soak 达标；句柄/线程无泄漏趋势。
- 兼容：数据目录、Schema v2、配置与旧录制历史保持不变；升级无需迁移。
- 文档：发布说明明确列出仍未验证项（窗口空白、kill 实测、低配、真实链路）。
