# AUDIT-SUMMARY — 项目综合评价与结论

> 基线：`c8ec7c2` / `v0.4.0`，2026-11-21。L2 只读审计，未修改代码、配置、数据库或发布产物。
> 配套文档：`PROJECT-AUDIT.md`、`DEFECT-REGISTER.md`、`P2-01-ANALYSIS.md`、`GITHUB-IMPROVEMENTS.md`、`V0.4.1-ROADMAP.md`

## 一、综合评价

**等级：B+（可对外交付，工程细节优于同类个人项目；短板集中在对外呈现与质量门禁，而非核心逻辑）**

- 架构分层干净：`domain / infrastructure / core` 无反向依赖，`app.py` 是唯一组合根，录制子进程只在管理线程操作。
- 数据安全设计扎实：V1→V2 迁移有写锁、事务、迁移前一致性备份、迁移后 6 类校验；`finish_recording` 幂等；Cookie 走 DPAPI。
- 进程管理成熟：Job Object + 三元组身份核验，避免 PID 复用误杀。
- 主要问题不是「代码写错」，而是「对外没说清」和「没有自动门禁」：README 仍指向 0.1.1、无 Release 链接、无 CI、无 LICENSE。
- 唯一已确认的功能级缺陷是 P2-01，影响面仅限日志/状态栏文案。

本轮**没有发现** P0（数据损坏、静默丢录、凭据泄露、启动不可用）级别问题。

## 二、明确定性问题

### 1. 哪些地方已经做得很好，不需要改动？

| 不要动 | 理由 |
| --- | --- |
| 分层结构与 `app.py` 组合根 | 依赖方向正确，无循环；拆分层没有收益 |
| 数据库迁移与校验链路（`db.py:228-607`） | 有写锁、事务、备份、6 类迁移后校验，属于高完成度实现 |
| 进程登记 + Job Object + 孤儿清理 | 三重身份核验，已覆盖崩溃与 PID 复用 |
| Cookie 的 DPAPI 存储与日志降噪 | `credential_store.py:70-89`、`logging_config.py:31-34` |
| 备份/恢复流程 | 恢复前做安全副本并二次校验（`backup.py:107-150`） |
| v0.4.0 GUI、图标、主题、托盘设计 | 已验收，PE 图标 10/10 匹配，重做只会引入回归 |
| 构建脚本与发布校验链 | `build.ps1` + `verify_icon.py` + `SHA256SUMS.txt` 已可用 |

### 2. 哪些问题必须优先修复？

1. **README 下载入口错误**（`README.md:161` 指向不存在的 0.1.1 包，全文无 Release 链接）——这是对外事实错误，优先级最高。
2. **最小 CI**——没有门禁，后续修复无法证明未引入回归。
3. **P2-01 事件契约**——已登记未修复，用户可见的文案错误。
4. **FFmpeg stderr 缺失**——不修代码不会更差，但「未知退出码」永远无法定论。

### 3. 哪些优化值得投入时间？

| 优化 | 投入 | 回报 |
| --- | --- | --- |
| README 首屏 + 截图（A-01） | 1 小时级 | 直接提升下载转化与新用户理解 |
| CI（A-02） | 半小时级 | 每次提交自动回归，长期收益最大 |
| P2-01（B-01） | 2 文件 ~30 行 | 消除唯一的已知功能瑕疵 |
| FFmpeg stderr（B-02） | 2-3 文件 | 让可靠性问题可诊断，避免继续「无法定论」 |
| 关闭流程提示（B-03） | 1 文件 | 消除 30 s 假死的观感 |

### 4. 哪些所谓优化实际上没有必要？

| 常见建议 | 结论 | 依据 |
| --- | --- | --- |
| 拆分 700+ 行的 `widgets.py` / `recording_service.py` | 不做 | 无缺陷证据；GUI 刚验收 |
| 引入 ORM 替换手写 SQL | 不做 | 现有迁移/校验测试完整，换框架风险高收益低 |
| 用 PyQt6 / Web 重写界面 | 不做 | 推翻已验收的图标、托盘、主题实现 |
| 给 `recordings` 立刻加索引 | 先测量 | 无任何查询耗时证据；`LIMIT 200` + 单用户场景大概率无感 |
| 单实例改 `Global\` | 不做 | 会让同一台机器的第二个 Windows 用户完全无法启动 |
| 把 Release 发布放进 CI | 不做 | 需仓库写权限，误操作风险大于收益 |
| 「托盘对象被 GC」 | 已排除 | `main_window.py:219/230` 持有 `self._tray` 强引用 |
| 「GUI 主线程里等 FFmpeg」 | 已排除 | 启停均走队列 + 管理线程 |

### 5. v0.4.1 应当包含哪些改动？

**建议范围（保持小批量、可回退）**：

1. A-01 README/下载入口修正（纯文档）
2. A-02 最小 CI（新增 1 个 workflow）
3. B-01 P2-01 事件契约修复（2 文件 + 4-6 条测试）
4. B-02 FFmpeg stderr 诊断落盘（注意不得记录命令行）
5. B-03 关闭流程可感知

**可延后到 0.4.2**：B-04 失败提示（需要抑制策略，避免提示风暴）、C-01 日志路径脱敏。

**明确不进 0.4.1**：任何 Schema 变更（C-02/C-03）、单实例作用域调整、结构重构。
