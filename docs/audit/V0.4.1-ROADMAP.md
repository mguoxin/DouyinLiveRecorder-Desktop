## P0 — 必做（对外正确性）

### A-01 README / 下载入口修正

- **目标**：新用户从 GitHub 仓库 30 秒内拿到 v0.4.0 正式包。
- **需要修改的文件**：`README.md`（首屏 25 行 + 修正 `L161` 的 0.1.1 残留 + 插入 2-3 张截图）。
- **预期收益**：消除「README 指向不存在的 0.1.1 包」这一事实错误；下载转化路径直达 Releases。
- **兼容性风险**：无（纯文档）。不影响任何运行行为。
- **测试要求**：人工点击 README 内所有链接，确认无 404；确认图片相对路径可渲染。
- **验收标准**：
  1. README 首屏出现 `releases/latest` 链接；
  2. 全文不再出现 `0.1.1-win64.zip` 作为「正式发布包」；
  3. ≥2 张 `docs/screenshots/release-0.4.0/` 截图可见。
- **回滚策略**：`git revert` 该文档提交；无数据影响。
- **参考**：`GITHUB-IMPROVEMENTS.md` G-01/G-02/G-08。

### A-02 最小 CI

- **目标**：任何 push/PR 自动跑无头测试，形成质量门禁。
- **需要修改的文件**：新增 `.github/workflows/ci.yml`（约 25 行）。
- **预期收益**：把「发布前人工重跑 276 项」变成常态自动校验；防止后续修复引入回归。
- **兼容性风险**：不影响本地/打包行为。唯一风险是 CI 时长与偶发 flaky（`test_single_instance.py`、`test_stability.py` 涉及时序）。
- **测试要求**：在 PR 上观察 3 次连续运行结果一致；记录 skipped 数量。
- **验收标准**：
  1. Windows runner 上 `pytest -q` 为 0 failed；
  2. 真实 FFmpeg 用例按预期 skip（日志中可见 skip 原因）；
  3. 总时长 < 10 分钟。
- **回滚策略**：删除 workflow 文件即可；不涉及代码。
- **注意**：CI 通过 ≠ 276 项全通过，必须单独记录 skip 数，不得混用两个口径。

## P1 — 建议进 0.4.1

### B-01 P2-01 事件契约修复

- **目标**：会话结束不再伪装成分段结束，消除「completed size=0」。
- **需要修改的文件**：
  - `src/dlrecorder/application/recording_service.py`（`_end_without_segment` 载荷、`_close_segment` 载荷补 `scope`）
  - `src/dlrecorder/presentation/main_window.py`（`_on_recording_finished` 增加会话分支）
  - `tests/test_recording_service.py`（新增 4 条用例，见 P2-01 文档第 8 节）
- **预期收益**：日志、状态栏与历史表口径一致；减少用户对「文件丢失」的误判。
- **兼容性风险**：事件载荷新增键；`app.py:239` 不读字段，不受影响；数据库、配置、打包均不变。旧版与新版可共用同一 `data\`。
- **测试要求**：P2-01 文档第 8 节 6 条；全量回归 ≥ 276 passed。
- **验收标准**：三类触发场景不再出现 `size=0` 文案；正常分段展示与 v0.4.0 截图一致。
- **回滚策略**：单提交 `git revert`；无 Schema 变更，回滚无需迁移。
- **详细方案**：见 `P2-01-ANALYSIS.md` 第 7 节（方案 A）。

### B-02 FFmpeg stderr 诊断落盘

- **目标**：给「未知退出码」类问题留下可分析证据，同时不泄露带签名的流地址。
- **需要修改的文件**：
  - `src/dlrecorder/infrastructure/ffmpeg.py`（`stderr=PIPE` 改为按行读入内存环形缓冲，或重定向到独立文件句柄）
  - `src/dlrecorder/application/recording_service.py`（分段结束时把最后 N 行 stderr 写入 `data/logs/ffmpeg-<recording_id>.log`，仅保留最近 20 个文件）
  - `tests/test_ffmpeg.py`（断言 stderr 被采集且不包含完整 URL）
- **预期收益**：把 Release 中登记的「FFmpeg 偶发未知退出码」从不可诊断变为可诊断；为 PR-04 闭环。
- **兼容性风险**：`stderr=PIPE` 若无人读取会阻塞子进程，**必须**用读线程或文件重定向，不能用裸 PIPE。文件落盘会增加磁盘占用（按 20 个文件 × ≤256 KB 上限计算，约 5 MB）。
- **测试要求**：伪装 FFmpeg 输出到 stderr 的用例；确认进程不阻塞、文件内容正确、日志不含 `http` 流地址。
- **验收标准**：人为制造非 0 退出，`data/logs/` 下出现对应 stderr 文件；全量测试通过。
- **回滚策略**：恢复 `DEVNULL` 即回到 v0.4.0 行为，单文件改动可 revert。
- **红线**：不得记录完整命令行（含签名 URL）。

### B-03 关闭流程可感知

- **目标**：避免关闭时最长 30 s 的「无响应」观感（PR-01）。
- **需要修改的文件**：`src/dlrecorder/presentation/main_window.py`（`closeEvent` 内先 `hide()` + 托盘气泡「正在停止录制…」，再同步 shutdown；记录耗时到日志）。
- **预期收益**：用户知道程序在收尾而不是卡死；日志可量化实际关闭耗时。
- **兼容性风险**：仅影响关闭瞬间的视觉；不改 `RecordingService.shutdown` 的超时值（避免影响录制数据完整性）。
- **测试要求**：手工在「正在录制」状态下关窗，确认窗口立即消失、进程在超时内退出；`test_app.py` 全量通过。
- **验收标准**：关闭耗时 ≤ 3 s（正常场景）；异常场景下窗口不再白屏无响应。
- **回滚策略**：单文件 revert。

### B-04 录制失败用户可见

- **目标**：最小化到托盘时也能感知录制失败（PR-02）。
- **需要修改的文件**：`src/dlrecorder/presentation/main_window.py`（或 `tray.py`）在 `recording_error` 上弹托盘气泡；托盘不可用时退回状态栏 + 日志页高亮。
- **预期收益**：减少「以为在录，其实早停了」的静默失败。
- **兼容性风险**：气泡过多会打扰；需做**同一房间 60 秒内只提示一次**的抑制。
- **测试要求**：模拟 `recording_error` 连续触发 3 次，断言只出现 1 次提示。
- **验收标准**：托盘可用/不可用两条路径均能提示；无提示风暴。
- **回滚策略**：单文件 revert；无持久化状态。

## P2 — 观察或延后

### C-01 日志路径脱敏

- **目标**：日志只记录相对录制目录的路径或文件名，降低分享日志时的隐私暴露。
- **文件**：`recording_service.py:870-885`、`main_window.py:516-522`。
- **收益**：中低（日志仅本地）；**风险**：低；**建议**：随手改，不必单独立项。

### C-02 历史查询测量 → 按需加索引

- **目标**：用数据决定是否需要索引，而不是凭直觉加 Schema 迁移。
- **先测量**：用 `tools/benchmark.py` 或临时脚本灌入 1 万 / 5 万行 `recordings`，测量 `list_recordings(status=...)` 与历史页加载耗时。
- **判定线**：若 p95 > 100 ms 或历史页出现可感知卡顿，再做 Schema v3（`CREATE INDEX idx_recordings_room_id ON recordings(room_id, id DESC)` 等）。
- **兼容性风险（若实施）**：Schema 版本 +1，需要新的迁移分支与回滚测试；旧版打开新库会因版本高于自身而拒绝（需确认现有版本检查行为）。
- **结论**：**0.4.1 不做**，先测量。无证据前不得宣称性能瓶颈。

### C-03 `recordings.error_message` 列

- **收益**：历史页可展示失败原因，替代翻日志。
- **风险**：Schema v3 迁移 + 备份/恢复/迁移校验全链路需要新用例；与 C-02 可合并为一次 Schema 升级。
- **结论**：延后到 0.5.0，与索引一起作为一次「有充分测试的 Schema 升级」。

### C-04 单实例改为 `Global\`

- **收益**：跨会话互斥。**风险**：多用户共享同一台机器时，第二个用户会完全无法启动（比现在更差）；改变互斥量名称还会导致新旧版本可并存。
- **结论**：**不做**。当前 `Local\` + 用户目录安装路径的组合已足够。

### C-05 发布脚本化

- **文件**：新增 `build/release.ps1`（见 GITHUB-IMPROVEMENTS G-06）。
- **结论**：可选，收益是减少发布时的手工失误；不改变产品行为。
