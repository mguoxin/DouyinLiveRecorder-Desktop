## 4. P1 关闭流程稳定性

### 4.1 「61 秒不退出」根因与修复 — PASS

根因（已复现）：主窗口最小化到托盘（隐藏）且存在活动录制时，`closeEvent` 中的
退出确认框以隐藏窗口为父，对话框不可见，事件循环停在嵌套模态循环，`closeEvent` 不返回。
日志无「主窗口关闭」，实测卡住 76s。

最小修复（`main_window.py`）：在 `ask_confirm` 之前检测「有活动录制且窗口不可见」，
先恢复并激活主窗口再弹确认框；不改变「确认前不停止录制、不关闭数据库」的语义。

| 证据 | 内容 |
| --- | --- |
| 修复前 | 探针 76s 未退出，日志无关闭记录；桌面复测首轮 61s 未退出 |
| 修复后（真实桌面探针） | 隐藏前 `hidden_before_close=True`；请求关闭后 `main_visible=True`、`main_minimized=False`；`QMessageBox「退出前停止录制」` 可见且 `dialog_parent_is_window=True`；点击确认后 `exit_code=0`、`close_seconds=1.23`、`ffmpeg_left=0`；录制文件 35,306,024 B |
| 单元回归 | `test_close_restores_hidden_window_before_confirm`（隐藏窗口 + 活动录制，确认框父窗口可见） |

### 4.2 关闭期间状态查询竞态 — PASS（本轮新发现并修复）

验收探针在关闭收尾阶段抛出 `TimeoutError`（`_on_task_stopped → _refresh_summary →
is_monitoring → future.result(timeout=5.0)`），原因是事件循环已进入退出流程，
`_is_running` 协程不再被调度，UI 线程等待 5s 后异常冒泡，属生命周期竞态。

修复（`task_manager.py`）：`is_running()` 在 `_shutdown_event` 已置位时直接返回 False；
超时按「未运行」处理并记录 WARNING；其他异常降级为 DEBUG，避免异常冒泡到 Qt 槽。
新增回归 `test_is_running_returns_false_once_shutdown_requested`。

修复后同一探针：无 `Traceback`、无 `TimeoutError`，`close_seconds` 由 6.5s 降至 1.23s。

## 9. 遗留风险清单

1. **许可（高，未关闭）**：DLL 内静态 LGPL 库的可重链接义务缺证据；v0.4.1 不应据此
   正式发布，处置见 3.5 方案 A/B。
2. **v0.4.0 历史附件（高）**：GPLv3 对应源码缺失；建议暂停公开下载，原 ZIP 不动。
3. **真实抖音链路（中，NOT TESTED）**：解析、拉流、断线续录、弱网行为未在本轮真实验证。
4. **窗口空白（中，未复现）**：见第 5 节，保留观察项与复现步骤。
5. **kill 兜底（低）**：Windows 下 terminate 近似强杀，kill 分支难触发。
6. **慢关闭无硬上限（低）**：>30s 仅提示不强制；保留以避免破坏录制文件与数据库。
7. **诊断日志多房间混写（低）**：共享写锁不截断但会交错，含本地路径不含凭据。
8. **低配真机（中）**：仅有 2 核亲和性模拟基准。
9. **候选包可重现性（低）**：`Compress-Archive` 时间戳导致哈希不可重现。
10. **FFmpeg 说明表述（低）**：`tools\ffmpeg\README.txt` 将 `zimg`（WTFPL）列为 LGPL 示例，
    后续修正为 WTFPL；不影响二进制与分发。
