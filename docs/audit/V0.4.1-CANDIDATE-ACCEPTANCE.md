## 4. B-02 专项验证（stderr）

### 4.1 验收中发现并修复的缺陷

初版实现每行执行 `stat` + `open` + `write` + `close`。在本机（Windows Defender
实时防护开启）实测：

- 30,000 行（约 3.8MB）stderr 排空耗时 **35.11s**；
- 相同数据用常开句柄写入仅 **0.01s**；
- 3.8MB 突增输出时管道被反压，子进程 30s 内无法写完 —— 真实 FFmpeg 会在
  同等情况阻塞在 stderr 写入，进而停住录制。

修复（`faaa49d`）：`_DiagnosticsLog` 进程内保持单一文件句柄，按写入字节计数轮转，
每次写入 flush；`close_streams()` 释放句柄。修复后同一负载 **0.46s**。

事件循环与线程顺序（代码审查 + 日志）：

1. `closeEvent` 置 `_shutdown_started`、`event.ignore()`，保持窗口可见并禁用中央区域；
2. 后台线程 `recording.shutdown()` → `service.shutdown()`；
3. 完成后 `shutdown_finished` 经 QueuedConnection 回主线程，`self.close()` + `app.quit()`；
4. `exec()` 返回后 `Application.shutdown()`（幂等）释放窗口；
5. 数据库仅在监控线程确认退出后关闭，避免后台写入失效；
6. 进程退出前 Job Object 关闭，兜底终止残留 FFmpeg。

### 6.2 许可与第三方义务 — FAIL（发布阻断）

随包材料（已从解压目录核对）：

- `_internal\LICENSE`（MIT，1101 B）；
- `_internal\THIRD_PARTY_NOTICES.txt`（4353 B，列 Python/PySide6/FFmpeg/SQLite/上游 MIT/httpx/h2）；
- `_internal\ffmpeg\LICENSE`（GPLv3 全文，674 行）；
- `_internal\ffmpeg\README.txt`（gyan 构建说明，标注 GPL v3 与 FFmpeg 源码 commit）。

实际二进制核查：

- `ffmpeg -version`：`9.0.2-essentials_build-www.gyan.dev`；
- `configuration` 含 `--enable-gpl --enable-version3 --enable-static`，静态链接
  `libx264`、`libx265` 等 GPL 组件；
- 源码地址 `https://github.com/FFmpeg/FFmpeg/commit/946fcce07b` 可访问（HTTP 200）。

阻断问题：

1. **FFmpeg 静态链接组件的对应源码义务未落实**：GPLv3 分发二进制需提供完整
   Corresponding Source（含 x264/x265 等静态库及其构建脚本）。当前仅提供 FFmpeg
   主仓 commit 地址，未提供这些库的源码或书面要约。独立进程调用不能免除二进制
   分发本身的义务。
2. **LGPLv3 文本缺失**：PySide6 以 LGPL-3.0-only 分发，包内无 LGPLv3 文本；
   本机 wheel 也仅含商业许可说明，需项目自行补充。
3. **Python PSF 许可文本缺失**：`_internal` 中无 Python 许可文件。
4. **certifi（MPL-2.0）未列入声明**：`_internal\certifi` 实际随包分发。

建议（发布前二选一）：

- 改用 **LGPL 版 FFmpeg**（本产品只需 `-c copy` 封装，不需要 x264/x265），
  可消除 GPL 静态链接源码义务；
- 或随包提供 FFmpeg 及其全部静态依赖的源码归档/书面要约，并补充 LGPLv3、
  PSF、MPL-2.0 文本。

## 9. 遗留风险清单

1. **许可合规（高）**：见 6.2；发布前必须处理，否则不建议对外分发。
2. **真实抖音链路未验收（高）**：解析、拉流、断线续录、弱网行为均未在本轮真实网络验证。
3. **重复关闭偶发未退出（中，未复现）**：首轮 5 次快速关闭出现 61s 未退出且无关闭日志，
   后续 5 轮均正常；建议正式发布前再跑一轮长时压力并保留日志。
4. **关闭无硬超时（中）**：状态栏承诺“最长约 30 秒”，但代码未实现强制上限；
   多房间或数据库异常时可能更久，甚至无限等待。
5. **kill 兜底未验证（低）**：Windows 下 terminate 基本等价强杀，kill 分支实际难触发。
6. **诊断日志多房间混写（低）**：同一文件共享写锁，不截断但会交错；含本地路径。
7. **`close_streams` 关闭管道顺序（低）**：若进程在 kill 超时后仍存活，关闭 stderr
   可能阻塞；当前正常流程不会触发。
8. **低配真机未验收（中）**：仍只有 2 核亲和性模拟基准。
9. **CI 通过数将与本地不同（低）**：CI 无 FFmpeg，真实 FFmpeg 用例跳过。
10. **候选包可重现性**：ZIP 由 `Compress-Archive` 生成，时间戳导致哈希不可重现；
    需要可复现构建时应固定文件时间。
