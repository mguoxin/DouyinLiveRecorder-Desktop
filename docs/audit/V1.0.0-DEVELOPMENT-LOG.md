## 2. v1.0.0 范围拆解

### M1 数据模型与迁移（Schema v4）

- `recordings` 增加媒体元数据与资产字段：
  `duration_s`、`width`、`height`、`video_codec`、`audio_codec`、`thumbnail_path`、`metadata_status`（none/pending/ready/failed）、`metadata_error`、`metadata_updated_at`、`favorite`、`note`。
- 新表（以实际实现为准）：
  - `tags(id, name UNIQUE, color, created_at)`
  - `recording_tags(recording_id, tag_id, created_at, PRIMARY KEY(recording_id, tag_id))`，双外键 CASCADE
  - `anchor_profiles(room_id PK, avatar_path, bio, note, created_at, updated_at)`，`rooms` CASCADE
  - `automation_rules(id, room_id, name, rule_type, enabled, priority, config, created_at, updated_at)`
  - `rule_runs(id, rule_id, room_id, status, started_at, finished_at, message, created_at)`，`rule_id` SET NULL
- 迁移 V3→V4：备份 + 事务 + 校验 + 幂等；V1→V4 链式。
- 验收：迁移/回滚/幂等/旧库升级/外键与索引完整性测试全绿（519 passed）。

### M2 媒体资产（P1）

- `infrastructure/media_probe.py`：调用本地 ffprobe 提取时长/分辨率/编码，生成缩略图；超时与失败分类。
- `application/media_probe_service.py`：单工作线程队列、去重、幂等、失败记录；录制中文件不入队；优先处理新完成录制。
- UI：录制库增加缩略图列/预览区、元数据展示、外部播放器入口。
- 验收：不阻塞 UI/录制；失败可重试；数据库与磁盘一致；缩略图路径可缺失。

### M3 资产组织（P1）

- 主播档案：别名、备注、头像；与 `rooms`/快照解耦。
- 标签：多标签、创建/删除、按标签筛选。
- 收藏与备注：录制级。
- 检索扩展：标签、收藏、时长、分辨率、排序（时间/大小/时长）。
- 验收：组合筛选正确；删除标签不删录制；空/异常状态可恢复。

### M4 自动化规则（P1）

- 规则类型一期：定时监控窗口、录制时间计划、自动归档开关、磁盘预警阈值、录制完成自动处理（探测/标签/归档）。
- `application/rules_engine.py`：状态机（pending/running/succeeded/failed/skipped）、幂等执行、优先级、冲突处理、执行历史。
- 与 MonitorService/RecordingService 通过只读查询与显式命令衔接，不侵入录制线程。
- 验收：重启后规则可恢复；重复触发不重复执行；失败有记录与通知。

### M5 统计与诊断（P1）

- `application/statistics_service.py`：日报/月报、主播维度、成功率/失败原因、存储趋势。
- 系统页：CPU/内存/线程/磁盘、统一事件与日志、诊断导出（沿用既有脱敏）。
- 验收：统计与数据库一致；无数据/异常状态有明确展示。

### M6 系统管理（P1）

- 配置备份/恢复、数据库备份/恢复（SQLite Backup API）、迁移助手、换机恢复清单。
- 版本检查与安全升级：仅提示 + 下载校验，不自动覆盖用户数据；升级失败可回滚。
- 验收：恢复前自动备份；失败不破坏现有库；版本兼容性检查有测试。

### M7 UI/UX 统一（必做）

- 设计规范落地：颜色/字体/间距/圆角/组件状态统一；抽取通用组件（按钮、状态徽标、空态、加载、错误提示）。
- 信息架构：直播间、录制历史、媒体库、自动化、统计、日志、设置。
- 响应式：窗口缩放、最小宽度、表格列策略；避免新增功能导致拥挤。
- 验收：核心页面在 1280×720 与 1920×1080 下无截断；空/加载/错误状态齐备。

### M8 回归与交付

- 全量测试、迁移/恢复专项、性能预算、打包 11 步闭环、短时长 soak、文档与报告。
- 构建基线、SHA-256、已知问题、风险评估、正式发布建议。

## 3. 架构约束

- 依赖方向保持 Presentation → Application → Domain；Infrastructure 不反向依赖 UI。
- 媒体探测、归档、规则执行各自独立线程/队列；UI 只拉取只读快照。
- 新增功能默认关闭或向后兼容；Schema 迁移先备份、失败回滚。
- 不引入不必要的第三方依赖；优先使用标准库与既有 PySide6/FFmpeg。
- 所有磁盘破坏性操作需显式确认；媒体探测只读。
