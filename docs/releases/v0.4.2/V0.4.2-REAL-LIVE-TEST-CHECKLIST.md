# v0.4.2 真实直播测试条件清单

| 项目 | 内容 |
| --- | --- |
| 目的 | 为 v0.4.2 最终验收提供可执行的端到端真实直播测试方案 |
| 状态 | 未执行；等待授权与测试环境 |
| 禁止 | 使用私人 Cookie、公开传播直播间/用户信息、向正式发布产物写入测试数据 |

## 1. 必须由负责人/项目方提供

| # | 条件 | 说明 |
| --- | --- | --- |
| 1 | 测试授权 | 明确允许对指定直播间进行录制测试 |
| 2 | 测试房间（直播中） | 至少 1 个稳定开播 ≥60 分钟的抖音直播间 `web_rid` |
| 3 | 测试房间（未开播） | 至少 1 个确认未开播房间，用于状态判定 |
| 4 | 无效 ID | 1 个不存在/非法 ID，用于异常路径 |
| 5 | 账号策略 | 默认匿名访问；如需 Cookie 场景，使用**专用测试账号**，由负责人在本机输入，不交付明文 |
| 6 | 网络条件 | 稳定宽带；另需可模拟断网/弱网（防火墙或代理开关） |
| 7 | 磁盘空间 | ≥10 GB 空闲，独立测试目录 |
| 8 | 时间窗口 | 端到端 ≥60 分钟；24h soak 单独申请 |
| 9 | 版本与哈希 | 记录候选 ZIP / EXE 的 SHA-256，确保测的就是候选包 |

## 2. 测试环境准备

1. 将候选包解压到独立目录（如 `%TEMP%\dlr-e2e-v042`），不要使用正式 `data\`。
2. 设置 `DLR_DATA_DIR` 指向独立基准目录（程序会在其下创建 `data\`）。
3. 确认无其他实例运行；确认 FFmpeg 版本 9.0.2。
4. 记录开始时间、系统版本、网络类型、磁盘类型。
5. 开启窗口诊断（可选）：`DLR_WINDOW_TRACE=1`。

## 3. 端到端步骤

### 3.1 启动与基础功能

1. 启动候选 EXE，确认标题为 `抖音直播录制工具 v0.4.2`。
2. 添加“未开播”房间，开始监控，确认状态为“未开播”，不启动 FFmpeg。
3. 添加无效 ID，确认提示明确且不误判开播。
4. 添加“直播中”房间，开始监控，确认 `LIVE / SUCCESS`。

### 3.2 自动录制

5. 开启自动录制，确认进入“录制中”并启动 FFmpeg（记录 PID）。
6. 检查文件生成与持续增长（每 30 秒记录大小）。
7. 检查历史记录出现“录制中”，Session 关联正确。

### 3.3 异常与恢复

8. 在任务管理器中结束该 FFmpeg 进程（模拟断流/崩溃）。
9. 确认房间进入“重连中 x/y”，不得提示为“不可恢复失败”。
10. 确认自动重新解析并在新分段恢复录制；恢复通知仅在文件实际增长后出现。
11. 断开网络 10–30 秒后恢复，观察是否续录或按预算重试。
12. 若直播间结束，确认状态转为“未开播/已结束”，收尾为 `completed` 或按真实结果记录。

### 3.4 停止、退出与重启

13. 手动停止录制，确认文件保留、历史更新、无 FFmpeg 残留。
14. 最小化到托盘，双击恢复；托盘右键退出；确认退出码 0。
15. 在录制中关闭主窗口，确认覆盖层、收尾完成、退出码 0。
16. 重新启动，确认历史仍可读、遗留 `recording` 被标记为 `interrupted`、无孤儿 FFmpeg。

### 3.5 证据采集

| 证据 | 要求 |
| --- | --- |
| 录制文件 | 保留原文件；记录路径、大小、起止时间 |
| 解码校验 | `ffmpeg -v error -i <file> -f null -` 退出码 0 |
| 数据库 | 仅查询测试库：`rooms/recordings/monitor_sessions` 关键字段 |
| 日志 | 使用整改后的脱敏日志；确认无绝对路径/Token |
| 界面 | 关键状态截图（录制中、重连中、历史、托盘） |
| 时间线 | 开始/开播/录制/异常/恢复/停止/退出时间点 |

## 4. 本地测试流可以覆盖 / 不能覆盖

| 场景 | 本地合成流 | 真实抖音 | 说明 |
| --- | --- | --- | --- |
| 打包依赖、启动、退出 | 可以 | 可以 | 本地即可 |
| FFmpeg 参数、文件增长、历史落库 | 可以 | 可以 | 但需标注合成 |
| 强杀/重连状态机 | 可以 | 可以 | 本地可重复 |
| 开播检测、状态映射 | **不可以** | **必须** | 依赖真实接口 |
| 流地址提取、清晰度选择 | **不可以** | **必须** | 签名/风控相关 |
| 直播自然结束行为 | 不可以 | **必须** | 合成流无法等价 |
| 真实风控/Cookie 失效 | 不可以 | **必须** | 需专用账号授权 |
| 24h 长稳 | 可先本地压测 | 建议真实 | 两者结论分开记录 |

> 本地合成流结果不得写入“真实直播通过”；报告中必须分别列出。

## 5. 通过标准（建议）

| 项 | 标准 |
| --- | --- |
| 真实直播连续录制 | ≥30 分钟，文件持续增长，无异常退出 |
| 断流恢复 | 强杀 FFmpeg 后 ≤30 秒内进入重连并恢复（受退避影响） |
| 数据一致性 | 文件大小与 `recordings.file_size` 一致；状态正确 |
| 通知语义 | 重连中不误报失败；恢复通知仅一次 |
| 退出清理 | 退出码 0，无 FFmpeg 残留，无未收尾 `recording` |
| 隐私 | 日志无绝对路径、Token、Cookie、完整流地址 |

## 6. 安全与合规

- 不读取、不导出、不提交用户的私人 Cookie；需要登录场景时由本机 DPAPI 保存。
- 不在公开 Issue/报告中粘贴真实流地址、房间号全文、截图中的用户信息。
- 测试结束删除临时数据与录制文件，或按负责人要求保留在隔离目录。
- 若无法取得授权，该项保持 **BLOCKED**，不得用合成流替代结论。
