## 1. 问题与根因

验收发现 `data/logs/app.log` 明文记录：

```
应用初始化，版本=0.4.2，数据目录=C:\Users\<用户名>\AppData\Local\Temp\...\data
FFmpeg 路径=C:\Users\<用户名>\...\_internal\ffmpeg\bin\ffmpeg.exe
```

根因：日志格式器只做文本拼接，没有统一脱敏；路径来自正常的 INFO 诊断日志（`app.py` 初始化日志），
并非异常路径。诊断导出另有脱敏，但原始日志被用户直接分享时会泄露用户名/安装路径（PR-03 残余）。

## 2. 整改方案

新增 `src/dlrecorder/infrastructure/redaction.py`，作为日志与诊断的**唯一**脱敏实现：

| 能力 | 规则 |
| --- | --- |
| Windows 绝对路径 | 支持盘符、反斜杠/正斜杠、空格、中文、括号；遇到 `,;，。；、）)]】` 等分隔符停止，避免吞掉后续正文 |
| 用户主目录 | 精确替换为 `%USERPROFILE%`（覆盖中文用户名与含空格路径） |
| 数据目录 | 精确替换为 `<data>` |
| URL | 整体替换为 `<url>`（含签名参数） |
| Cookie / Authorization | 请求头整体替换 |
| Token 参数 | `token/access_token/sessionid/a_bogus/...` 替换值 |
| 邮箱 / IPv4 | 替换为 `<email>` / `<ip>` |
| 房间号 | 仅在诊断导出中掩码；日志保留，便于定位 |

日志侧新增 `RedactingFormatter`，在最终格式化结果（含 traceback）上脱敏，同时挂到
`RotatingFileHandler`（5 MiB × 3）与控制台 `StreamHandler`。

## 5. 限制与残余风险

1. 日志仍保留直播间 ID（无个人身份信息），用于定位；诊断导出会掩码。若负责人要求日志也不保留，可再调整。
2. 路径后若紧跟无标点的正文，可能被一并脱敏（隐私优先，允许过度脱敏）。
3. 用户主目录之外的任意路径依赖通用正则；极端自定义路径（含 `;` 等分隔符）可能只脱敏前半段，但不会出现用户名。
4. 历史日志文件不会自动清洗；整改只影响新写入内容。
