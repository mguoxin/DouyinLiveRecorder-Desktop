### 2.1 事件契约（向后兼容）

保留原信号，新增结构化信号，未破坏既有消费者：

- 保留：`recording_error = Signal(int, str)`
- 新增：`recording_error_info = Signal(int, dict)`，载荷 `{room_id, phase, category, retryable, message}`
  - `phase ∈ {start_failed, runtime_failed, session_failed, db_failed}`
  - `category ∈ {disk, output_dir, network, auth, process, database, duplicate, other}`
- 新增：`recording_recovered = Signal(int, dict)`，仅在续录分段**首次观察到文件增长**后发出
- `recording_finished` 载荷新增：`scope(segment|session)`、`status`、`requested`、`will_retry`
- `recording_started` 载荷新增：`resumed`、`attempt`
- `recording_reconnecting` 载荷：`attempt / max_attempts / delay_s / error / exit_code`

两条错误路径均已覆盖：`recording_error`（含 `recording_error_info`）与 `recording_finished(scope=segment, status=failed)`；后者在 `will_retry=True` 时由通知层静默，仅终态失败提示。

## 4. 诊断导出安全测试报告（W-03）

### 4.1 设计与实现

- 入口：设置页“导出诊断报告…”，用户主动触发，保存位置由用户选择。
- 输出：4 个条目
  - `report.json`
  - `report.md`
  - `logs/app-errors.txt`
  - `logs/ffmpeg-stderr.txt`
- 上限：ZIP ≤ 1 MiB（`MAX_ZIP_BYTES`），内存构建后循环裁剪日志。
- 读取策略：日志尾部读取（app 256 KiB / ffmpeg 128 KiB、200 行）。
- 脱敏顺序：ANSI → 数据目录 → 用户主目录 → URL → Cookie/Authorization 头 → 密钥参数 → 邮箱 → IPv4 → Windows 路径 → 房间号（保留首 2 末 2）→ 2000 字符截断。
- 二次扫描：`_scan_leak` 丢弃仍疑似含敏感内容的行；白名单字段优先，不确定即省略。
- 数据库检查：只读 URI `file:<posix>?mode=ro` 执行 `PRAGMA quick_check` 与表计数，不写入、不锁库。
- 写入：临时文件 + `os.replace` 原子替换；不覆盖已存在文件；取消或失败清理临时文件。
- 不上传：无网络调用、无 socket。

### 4.2 自动化测试证据（11/11 PASS）

| 用例 | 断言结果 |
| --- | --- |
| 敏感字符串注入（Cookie/Authorization/URL/密钥/邮箱/IP/路径/房间号） | 输出不含原值，替换为 `<redacted>` / `<url>` / `<path>` / `95*******22` |
| ZIP 条目精确 4 个 | 无数据库文件、无 `SQLite format 3` 字节 |
| 导出前后 DB 文件哈希不变 | PASS |
| 超大日志封顶 | 输出仍 ≤ 1 MiB |
| 注入 `MAX_ZIP_BYTES=64KiB` | 日志被裁剪并标记 truncated |
| 导出取消 | 无输出文件、无临时残留 |
| 磁盘写入异常 | 抛出 `DiagnosticsError`，临时文件清理 |
| `os.replace` 失败 | 清理临时文件 |
| 目标已存在 | 生成不覆盖的唯一路径 |
| 无网络套接字 | PASS |
| DB 被独占锁 | 仍可导出（只读不阻塞录制） |
