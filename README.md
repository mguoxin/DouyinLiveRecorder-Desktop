# 抖音直播监控与录制工具（Windows 桌面版）

基于 Python 3.12 + PySide6 Widgets + SQLite 的轻量级 Windows 桌面应用。

当前版本：**0.1.1**（Git Tag `v0.1.1`）。正式发布包：
`release\DouyinLiveRecorder-0.1.1-win64.zip`，解压后直接运行 `DouyinLiveRecorder.exe`
（onedir 便携版，内置 FFmpeg）。发布验收详情见 [RELEASE_REPORT_0.1.1.md](docs/RELEASE_REPORT_0.1.1.md)，
0.1.0 的完整发布记录见 [RELEASE_REPORT_0.1.0.md](docs/RELEASE_REPORT_0.1.0.md)。

## 当前实现状态

已实现并通过自动化测试（离线）：

- 直播间配置：添加、编辑、删除、持久化与参数校验；删除房间保留录制历史与文件。
- 监控任务：多房间并发监控、任务隔离、停止与异常退出处理、Session 历史记录；瞬时排队已满只提示一次并自动重试，不再刷屏报错。
- 单实例运行：Windows 命名互斥量，进程终止前不提前释放。
- HTTP 层：传输错误分类（超时 / DNS / TLS / 连接 / 协议 / 非法 URL）与可注入客户端。
- 解析层：生产默认 `EngineDouyinParser`（0.2.0 起），主链路移植上游 ihmily/DouyinLiveRecorder 的
  `webcast/room/web/enter` + `a_bogus` 签名，返回小体积 JSON（实测 0.4–0.8s/房间），并保留旧页面
  React Flight 解析器作为第二数据源回退；风控页单独归类为 `RISK_CONTROL`；`DLR_PARSER=mock` 仅用于开发/测试。
- 录制闭环：FFmpeg 子进程启停、输出增长检测、异常退出处理、录制历史持久化、异常退出恢复。
- 自动录制：确认开播后自动开始，停止监控 / 删除房间后自动停止；开关持久化。
- GUI：房间列表、编辑对话框、录制控制、自动录制开关、录制历史、打开录制目录。
- 软件设置：FFmpeg 路径（含可用性检测）、录制目录、监控间隔、磁盘最低剩余空间；持久化到 `settings` 表。
- 数据保护：磁盘空间不足时阻止开始录制或停止正在进行的录制（不自动删除文件）；数据库一键备份，恢复请求在下次启动时安全执行并保留当前库的安全副本。
- 交付健壮性：打包运行的数据目录固定在 EXE 所在目录；目录不可写或数据库损坏时，启动会给出可读提示并以退出码 4 结束；备份/恢复在存在 WAL 时也使用 SQLite Backup API 取得一致性副本。

已确认的设计取舍：

- 房间不存在：实测公开页对无效 ID 返回 200 但没有目标房间数据，统一归类 `API_MALFORMED`，不会误判为直播。
  对照探测显示存在但未开播的房间仍有房间对象（`status=4`），但页面结构变化或风控页也可能无房间数据，
  因此按“解析异常”处理，不单独映射 `ROOM_NOT_EXIST`。
- 录制文件：不自动删除任何文件，由用户自行管理；删除房间也不删除历史与文件。
- 数据目录：源码运行使用当前工作目录；打包程序使用 EXE 所在目录，可用 `DLR_DATA_DIR` 覆盖（自动化验收用于隔离数据，不影响普通用户）。

尚未完成或未验证：

- 解析主链路依赖抖音接口；接口或签名规则变化时需要同步上游引擎版本（回退链路仍可独立工作）。
- 长时间运行：24 小时采样已完成（20 房间全程稳定、内存 34–60MB 无增长、线程数稳定）；
  期间发现并修复“录制目录被外部删除时磁盘检查每秒刷日志”的缺陷。
- 低配机器（i3 / 4GB）验收：待执行，使用 `tools\acceptance_low_spec.ps1` 生成 JSON 报告。

## 软件设置

主窗口工具栏「设置」可修改：

- FFmpeg 可执行文件：支持绝对路径或命令名，「检测」会执行 `ffmpeg -version` 验证。
- 录制目录：修改后对新开始的录制生效，不移动已有文件。
- 监控间隔：对之后启动的监控任务生效。
- 磁盘最低剩余空间：低于该值时阻止开始录制；录制过程中低于该值时停止录制并标记失败。

## 备份与恢复

- 「备份数据」使用 SQLite Online Backup API 生成一致性备份并校验完整性。
- 「恢复备份」只登记恢复请求；退出并重新启动后才会替换数据库。
- 恢复前会自动把当前数据库复制到 `data/backups/pre-restore-*.db`，失败时保留当前数据库。
- 备份与恢复均不删除录制文件。

## 运行

```powershell
# 安装依赖（已提供 .venv 时可直接使用）
.venv\Scripts\python.exe -m dlrecorder
```

录制功能依赖 FFmpeg：

- 项目已内置 FFmpeg 9.0.2：`tools\ffmpeg\bin\ffmpeg.exe`，程序启动时自动使用；
- 打包程序内同样内置（`_internal\ffmpeg\bin\ffmpeg.exe`），无需单独安装；
- 也可在「设置」中指定其他 FFmpeg 路径，并用「检测」验证；
- 若路径无效，开始录制时会报告“FFmpeg 启动失败”，不会影响监控功能。

## 数据与文件

- 数据库：`data/app.db`（SQLite，Schema V2）。源码运行位于当前工作目录；打包程序位于 `DouyinLiveRecorder.exe` 同级的 `data\`。
- 录制文件：`data/recordings/`。
- 日志：`data/logs/`。
- 删除房间不会删除历史录制记录或录制文件。
- 程序异常退出后再次启动，会把遗留的 `recording` 记录标记为 `interrupted`，并按磁盘实际大小回填文件大小。

## 故障排查

- 启动后弹出“程序启动失败”：检查程序所在目录是否可写、`data\app.db` 是否被其他程序占用或损坏；
  可先用「恢复备份」使用有效备份，或把 `data\app.db` 改名保留后重新启动。
- 看不到之前的房间或历史：确认启动的是同一份程序。打包版数据固定在 EXE 同级 `data\`，
  与从哪个工作目录启动无关；用快捷方式启动时请勿复制走 EXE 所在文件夹以外的数据。
- 提示“FFmpeg 启动失败”：在「设置」中重新选择 FFmpeg 路径并点击「检测」；
  打包版内置 FFmpeg，若被杀毒软件隔离需恢复或重新解压程序目录。
- 提示磁盘空间不足：清理磁盘或调低「磁盘最低剩余空间」阈值；程序不会自动删除任何录制文件。
- 录制历史出现 `interrupted`：上次程序异常退出，重启后按实际文件大小回填，属预期行为。
- 提示“已在运行”：单实例保护生效，请关掉已运行的主窗口后再启动。
- 房间一直“未知”或无状态更新：检查网络与 `data\logs\app.log`；公开页结构变化时解析器可能需要同步维护。
- 退出时窗口短暂无响应：正在按 q → terminate → kill 的顺序停止 FFmpeg，属正常收尾。
